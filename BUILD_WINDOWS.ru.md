# Сборка Voxy на Windows

> **Статус:** порт на Windows написан, но **ещё не проверен на реальном
> железе**. Пока Voxy собирали и тестировали только на Mac с Apple Silicon.
> CI (GitHub Actions, `.github/workflows/ci.yml`) собирает его на
> `windows-latest`. Это доказывает, что код компилируется, но не то, что
> приложение работает. Отчёты с настоящих Windows-машин очень нужны (см.
> [Что проверить](#что-проверить)).

Инструкция рассчитана на 64-битную (x64) Windows 10/11 и PowerShell.

## Что понадобится (один раз)

1. **Microsoft C++ Build Tools.** Скачайте с
   https://visualstudio.microsoft.com/visual-cpp-build-tools/ и отметьте
   нагрузку **«Desktop development with C++»** («Разработка классических
   приложений на C++»).
2. **Rust** через rustup: установщик с https://rustup.rs или
   `winget install --id Rustlang.Rustup`. Тулчейн должен быть **MSVC**
   (готовые библиотеки sherpa-onnx собраны только под MSVC):
   ```powershell
   rustup default stable-msvc
   ```
3. **WebView2 Runtime.** В Windows 11 и в Windows 10 начиная с версии 1803 он
   уже есть. Если у вас его нет, скачайте с
   https://developer.microsoft.com/microsoft-edge/webview2/. Установщик,
   который вы соберёте ниже, тоже сам скачает и поставит WebView2 там, где его
   нет (так Tauri делает по умолчанию).
4. **Git**: `winget install --id Git.Git -e` (или https://git-scm.com).
5. **Tauri CLI v2**:
   ```powershell
   cargo install tauri-cli --version "^2.0.0" --locked
   ```

Node.js и npm не нужны: интерфейс — это обычные статические файлы в `ui/`.

Для первой сборки нужен интернет. Кроме Rust-крейтов, которые скачивает
Cargo, она скачивает ещё две вещи:
- build-скрипт sherpa-onnx берёт готовый архив статической библиотеки
  (`sherpa-onnx-v<версия>-win-x64-static-MT-Release-lib.tar.bz2`, около
  120 МБ) из GitHub-релизов sherpa-onnx;
- Tauri при первой сборке установщика скачивает набор инструментов NSIS.

## Получение исходников

```powershell
git clone https://github.com/DIZRAID/voxy
cd voxy
```

Если репозиторий приватный, Git попросит войти в GitHub-аккаунт, у которого
есть к нему доступ.

**Другой вариант: zip с Mac.** Папку `src-tauri/target` не берите: это кэш
сборки, он всё равно пересоздаётся.

```bash
# на Mac
cd ~/Desktop && zip -r voice.zip voice -x "voice/src-tauri/target/*"
```

После распаковки на ПК папка будет называться `voice`, а не `voxy`.

## Сборка

```powershell
cd src-tauri
cargo tauri build
```

В release-профиле включены LTO и `codegen-units = 1`, поэтому первая сборка
идёт долго.

Что получится:

- Установщик: `src-tauri\target\release\bundle\nsis\Voxy_0.1.0_x64-setup.exe`.
  Tauri называет его по шаблону `<productName>_<version>_<arch>-setup.exe`,
  а `productName` и `version` берёт из `src-tauri/tauri.conf.json`.
- Обычный исполняемый файл: `src-tauri\target\release\voxy.exe`.

В `bundle.targets` указано `["app", "nsis"]`. `app` — цель только для macOS,
на Windows Tauri её пропускает, так что собирается только NSIS-установщик.

Для разработки есть `cargo tauri dev`: собирает отладочную версию и сразу её
запускает. Чтобы лог шёл в консоль, а не в файл:

```powershell
$env:VOXY_LOG_STDERR = "1"
cargo tauri dev
```

### Если сборка упала

- **Ошибка на этапе линковки указывает на `link.exe` из Git** (например,
  `...\Git\usr\bin\link.exe`). В заметках sherpa-onnx по Windows сказано, что
  Cargo может взять `link.exe` из Git вместо линкера MSVC. Чтобы это
  исправить, откройте **Developer PowerShell for VS** (ставится вместе с
  Build Tools), укажите Cargo линкер MSVC и соберите заново в этом же окне:
  ```powershell
  $env:CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_LINKER = Join-Path $env:VCToolsInstallDir 'bin\HostX64\x64\link.exe'
  ```
- **Не скачивается архив sherpa-onnx** (нет интернета или мешает файрвол).
  Скачайте `sherpa-onnx-v<версия>-win-x64-static-MT-Release-lib.tar.bz2`
  вручную с https://github.com/k2-fsa/sherpa-onnx/releases. `<версия>` должна
  совпадать с версией `sherpa-onnx-sys` в `src-tauri/Cargo.lock` (на момент
  написания 1.13.8). Положите файл в отдельную папку и соберите так:
  ```powershell
  $env:SHERPA_ONNX_ARCHIVE_DIR = "C:\путь\к\этой\папке"
  cargo tauri build
  ```
  Архив распакуется в `src-tauri\target\sherpa-onnx-prebuilt\`.

## Первый запуск

- Установщик не подписан сертификатом, поэтому SmartScreen может показать
  «Система Windows защитила ваш компьютер». Нажмите **«Подробнее» →
  «Выполнить в любом случае»**. Установка идёт для текущего пользователя и не
  требует прав администратора (режим NSIS в Tauri по умолчанию).
- Voxy живёт в **области уведомлений** (трее) и **при первом запуске не
  открывает ни одного окна**. Windows 11 может спрятать новый значок под
  стрелку **^**. В меню значка есть **Settings…** и **Quit Voxy**. Повторный
  запуск Voxy (например, из меню «Пуск») тоже открывает настройки уже
  работающей копии.
- Модель по умолчанию, Parakeet TDT 0.6B v3 (~670 МБ), сама скачивается с
  Hugging Face в `%APPDATA%\com.dizraid.voice\models\`. Прогресс виден в
  настройках на вкладке **Model**. Если нажать хоткей до того, как модель
  будет готова, островок покажет «Model is not ready yet».
- Настройки и история лежат в `%APPDATA%\com.dizraid.voice\` (в
  `settings.json` и `history.json`).
- Горячая клавиша по умолчанию — **правый Ctrl**. Чтобы сменить её, откройте
  **General → Change** и нажмите новую клавишу (Esc отменяет).
- Хоткею и вставке **не нужны отдельные разрешения**: в Windows нет аналогов
  Accessibility и Input Monitoring из macOS. А вот микрофон подчиняется
  настройкам конфиденциальности Windows. Если островок пишет «Microphone
  unavailable», откройте **Параметры → Конфиденциальность и защита →
  Микрофон** (в Windows 10: **Параметры → Конфиденциальность → Микрофон**) и
  разрешите классическим приложениям доступ к микрофону.
- API-ключи онлайн-провайдеров (OpenAI, Groq, ElevenLabs) хранятся в
  **Диспетчере учётных данных** Windows.

## Отличия от macOS-версии

- **Хоткей:** вместо CGEventTap работает низкоуровневый клавиатурный хук
  (`WH_KEYBOARD_LL`). Хук ставится один на процесс и только слушает: нажатие
  всё равно доходит до активного приложения.
- **Островок:** выреза камеры нет, поэтому в покое пилюля скрыта. Во время
  записи, распознавания или при ошибке она выезжает от верхнего края по центру
  основного монитора. Это обычное прозрачное окно поверх всех окон (без
  NSPanel). Клики проходят сквозь него, кроме как во время записи: тогда по
  нему можно кликнуть, чтобы появилась кнопка Cancel.
- **Вставка:** синтетический **Ctrl+V** по виртуальному коду клавиши, поэтому
  работает на любой раскладке, в том числе на кириллице. Как и на macOS,
  прежний текст в буфере обмена потом возвращается на место.
- **Звуки:** системные звуковые алиасы Windows, поэтому они следуют вашей
  звуковой схеме: `SystemAsterisk` (старт), `SystemDefault` (стоп),
  `SystemHand` (ошибка).
- **Лог:** `%LOCALAPPDATA%\Voxy.log`.
- **Имена клавиш** в `settings.json` общие для обеих систем у Ctrl, Shift,
  Alt, Win (на Mac — Command), Caps Lock, F1–F19 и
  Home/End/PageUp/PageDown/Insert. На Windows `MetaRight`/`MetaLeft` — это
  клавиши Win, а `AltGr`/`Alt` — правый и левый Alt. `Function` (Fn) есть
  только на macOS. Любая другая клавиша сохраняется платформенным кодом
  (`Key0xNN`) и между системами не переносится.

## Известные недочёты

Всё это найдено при чтении кода, на реальной машине пока никто не видел.

- Значок в трее — чёрный глиф, нарисованный как «шаблонное» изображение macOS,
  которое macOS сама перекрашивает под строку меню. Windows показывает его как
  есть, так что на тёмной панели задач он может быть плохо виден.
- В интерфейсе местами остались упоминания Mac (например, «On this Mac» на
  вкладке Model).
- Вставка в приложения, запущенные от администратора: Windows (UIPI)
  блокирует синтетический ввод из обычного процесса в окна с повышенными
  правами. Смотря как Windows об этом сообщит, либо ничего не вставится, либо
  островок покажет «Paste failed — text kept in clipboard», и текст останется
  в буфере обмена. В любом случае распознанный текст сохраняется на вкладке
  **History**.

## Что проверить

Если запускаете Voxy на Windows, полезнее всего проверить вот что:

1. Установщик отрабатывает, значок Voxy появляется в области уведомлений.
2. Модель скачивается до конца (Settings → Model).
3. В Блокноте: зажать правый Ctrl, сказать фразу, отпустить. Текст появляется
   у курсора.
4. Во время записи островок выезжает сверху по центру. Клик по нему
   показывает Cancel.
5. Вставка работает при включённой русской раскладке.
6. Работают режимы Hold / Toggle / Dynamic (вкладка Recording) и смена
   хоткея.
7. Работает автозапуск (Launch at login на вкладке General).
8. Сохраняется API-ключ онлайн-провайдера.

Если что-то не так, приложите `%LOCALAPPDATA%\Voxy.log` к issue на
https://github.com/DIZRAID/voxy/issues.

## Ускорение на NVIDIA GPU (опционально, потом)

Сейчас распознавание идёт на CPU. Сборка использует стандартные готовые
библиотеки sherpa-onnx, а `asr.rs` не задаёт `provider`, поэтому sherpa-onnx
работает со своим значением по умолчанию (CPU). Для CUDA понадобятся три
вещи: сборка sherpa-onnx с поддержкой CUDA в виде динамических библиотек
(фича крейта `shared` вместо стандартной `static`, плюс
`SHERPA_ONNX_LIB_DIR`), её DLL в составе установщика и параметр `provider` в
конфиге модели в `asr.rs`.
Вернёмся к этому, когда CPU-версия стабильно заработает на Windows.
